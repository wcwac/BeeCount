## 明确边界

- 真实支付应用的 22 个包名全部提供适配器，尚未分别验证当前真实版本/OEM 系统。云端只运行自有合成页面，不运行原 APK。
- 采集规则先保留页面判断、字段顺序和回调状态；原规则内部仍有历史 Double 算术。候选入账边界使用严格十进制，超精度会给 INVALID_AMOUNT，不能声称完全消除了所有历史计算差异。
- 普通外币流水可进入账本；统计、预算默认仅计算该账本币种并在界面明示，不折算。账户资产按币种分组。复杂金融限定同币种。
- CSV只交换普通收支，最多每批2000条；金融关联、候选及处理回执用完整ZIP。ZIP上限512MiB、单表128MiB、单附件16MiB、总行数100万、附件最多1万。
- 不导入任何旧版本备份。新应用自己的ZIP覆盖恢复，不合并数据库；认证/系统权限与目录授权不转移。
- 分期消费在有还款后不直接退款/删除，以明确阻止破坏计划和已还本金。复杂撤销需先处理关联。
- Release 空库首页在 API 36 x86_64 模拟器的一次内存快照为 PSS 31,516 KiB（约 30.8 MiB）、RSS 165,992 KiB（约 162.1 MiB）。这不是后台常驻、真实手机或长期浮窗循环的测量，不能据此宣称性能优于 73 版；四种状态和持续增长检查仍待补齐。
- 备份恢复、CSV、投资、目标、周期、应用锁及桌面组件已有实现和静态交叉审查，本轮没有逐项完成设备端到端验收。API 26、真实厂商系统、深色、大字体和键盘组合也没有完成全面设备覆盖。
- 新界面不复刻一木像素，不包含九宫格、动态资源名、模型、词典或原二进制。

## 静态审查中已修的问题

- 采集服务与桌面组件冷启动统一经过恢复检查，后台不依赖主页面初始化。
- 候选修订不覆盖用户在浮窗中的编辑，不因再绘制重复弹出已搁置浮窗。
- 恢复暂停采集、排空任务、递增数据代际，事务后收尾失败在同一进程恢复；旧窗口和表单失效。
- 文件导入不移除原页面组合；配置变化通过保留作业和稳定草稿ID交付附件。
- 锁定状态撤掉独立Dialog窗口，隐藏页面语义，禁止导入确认越过锁屏。
- 报销本金、退款恢复分类、分期父账单约束和跨币种统计统一到写入和查询层。

最终发布前静态核对还收紧了分期备份的正反向付款关联、账户/币种和总费用校验，防止同一还款被多期复用或已付款被恢复成未还。

浮窗与候选页切入完整编辑时携带有界临时草稿，保留未提交输入；代际变化/进程终止会使草稿失效，界面明确提示。设备检查等待真实系统事件掩码、窗口读取能力和工具身份生效后再打开支付页面。

保存与提交后导航/刷新分别处理，界面回调异常显示操作已完成，不再把已写入账务误报为保存失败。
