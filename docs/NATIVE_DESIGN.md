# 原生离线版实现设计

依据用户确认的《BeeCount 原生离线版详细设计 v1》，2026-10-25。Android 8.0+，包名 `io.github.wcwac.beecount.nativeapp`；新库 schema 1，不导入旧应用数据。

## 模块与依赖方向

```text
domain ← data ← ui
   ↑              ↑
capture ←─────── app
```

- domain：币种、整数金额、账务命令、候选证据、配置及接口；不依赖 Android 或 Room。
- data：Room 表、分页和聚合查询、原子账务入口、推荐和候选身份、周期/分期/投资计算。
- capture：无障碍服务、节点所有权、有界顺序队列、窗口选择、22 包名/15 处理器。处理器只产出候选。
- ui：Material 3 主题、四栏页面、类型化 Navigation、ViewModel/StateFlow、统一表单和选择器。
- app：应用容器、独立生命周期 Compose 浮窗、权限、认证、文件交换、WorkManager、RemoteViews。

使用构造器与应用容器组织依赖，不引入 DI 框架、事件总线、多进程、动态插件或大型图表框架。工具链固定 AGP 9.2.1 / Gradle 9.4.1 / JDK 17 / SDK 36；Kotlin 2.4.21 沿用现有 Flutter 分支已选版本，不声称最新。新增依赖固定版本，Compose 统一 BOM 2025.08.00。

## 账务一致性

金额从十进制字符串严格解析为最小货币单位 Long；份额和利率使用明确精度十进制。账户全局共享，余额来自账户变动之和。期初余额也是业务记录。无汇率时绝不跨币种求和。

`FinancialWriter.execute` 在 Room 事务中完成：操作 UUID/内容指纹检查、预期修订号与币种检查、记录与账户影响、关联与候选状态、操作回执。事务完成后才更新窗口和组件。重复 UUID 不重复入账；不同内容不得复用 UUID。候选重复确认返回原账单。

本金与手续费/利息分开：转账、还款、借贷结算、分期本金不计普通收支；退款按发生日期冲减原分类；报销通过应收记录与回款处理；投资日志独立于现金账户。编辑替换账户影响，删除/恢复校验关联，永久清除保留最小处理回执。

## 采集与确认

```text
实时权限和监听范围 → 顺序队列 → 同包同窗口根/交互窗口/有效来源
→ 规则与跨页面状态 → 标准候选与证据 → Room 待确认
→ Compose 浮窗或候选页面 → 统一账务命令
```

事件回调取得节点所有权，不持有 AccessibilityEvent。单消费者最多 32 个任务；内容事件按边界合并，状态事件保序。读取上限 2048 节点、512 文本、深度 64，超限拒绝解析。读取完成释放节点再写数据库。

可靠交易身份与商户订单参考分开。弱证据只合并同一待确认会话。不同应用不凭金额商户盲目合并。共享处理器的应用保持独立状态。候选先入库，浮窗失败仍保留候选；已编辑内容不被后续观察覆盖。

真实悬浮窗权限检查通过后创建 ComposeView 和独立 Lifecycle/SavedState/ViewModelStore owner，关闭时销毁并注销监听。自动保存只有实际显示、证据强、账户确定且采集仍连接才进行 5 秒倒计时；编辑/锁屏/权限和配置变化停止。手工和倒计时经过同一事务入口。

## 数据保护和后台

ZIP 按表流式导出，仓储维护锁保证快照一致，事务内不复制文件。恢复在暂存 Room 库验证引用、金额、账户影响、候选和回执，再暂停采集/关闭浮窗/递增代际，在一个 SQLite 事务替换业务数据。持久阶段标记和提交回执在进程重启时决定清理或保留新附件。

附件私有目录保存、系统选择器导入。CSV 自有格式包含金额、币种、时间、账户分类、标记与手续费，只导入普通收支；复杂关系用完整 ZIP。自动备份写用户指定目录，保留 7/14/30 份。WorkManager 仅处理周期候选与每日备份，不参与实时采集。

## 性能与界面

账单 Paging 每页 50、缓存目标 200；稳定 UUID；统计以 SQL 按范围聚合，不能使用当前分页当总账。界面生命周期收集 Flow，不同步查询数据库。Compose Material Surface 统一弹窗和主题，不携带原九宫格背景。Coil 只加载本地缩略图，缓存设上限。

后台不创建 Activity/图表/ComposeView，不启动额外采集进程，不轮询保活。Release 开启代码和资源压缩，云端检查同一个压缩签名 APK。最终性能评价须区分模拟器与真实手机，框架更换本身不构成性能证明。

## 交付与验证

只在 GitHub Actions 手动触发；一次流水线独立收集编译、核心断言、lint、APK 权限/签名、同一模拟器关键业务与截图、Release 启动证据，全部通过后发布本次产物。构建失败的后续依赖阶段标记失败或阻塞，不计通过。目标 5 个集中验收节点，实际每轮记录在实施清单。
